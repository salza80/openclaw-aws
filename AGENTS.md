# Repository guidance

This is an AWS-only CLI for OpenClaw deployments. Keep TypeScript on major version 6. Preserve v1 configuration, deployment names and existing SSM parameter paths. Do not add runtime registries, Hermes adapters or another model router.

- Link completed work with `Closes #<issue>` in the pull request description before merging so GitHub closes the issue automatically. Keep routine progress in the local execution plan instead of adding issue comments. Preserve deferred validation explicitly in that plan and the relevant remaining issue; issue closure must not be described as proof that an unrun test passed.

- CLI commands collect inputs, display plans and handle errors. Share provisioning through `src/operations/deployment.ts`; commands must not call other command handlers. `init` and `create` share the configuration workflow.
- `src/aws/target.ts` resolves credentials per target without modifying `process.env`. Pass that target to AWS clients. CDK child processes must use a captured configuration snapshot instead of rereading editable files, plus a private working/home directory so concurrent assemblies and unrelated CDK settings cannot interfere. Resolve a fresh, sufficiently long-lived child environment for each CDK attempt. Never persist or log credentials, provider keys, tokens or raw native auth results.
- Use `src/aws/ssm.ts` for bounded remote execution and `src/openclaw/commands.ts` for the Ubuntu/private-prefix/legacy-NVM environment and native structured results. Check status, exit code and truncation before interpreting output. Native reads must not send model prompts unless explicitly requested.
- Serialize shared Gateway mutations per hosting deployment using the operations lock. Native agent IDs do not own EC2 instances or separate deployment locks.
- Bedrock invocation grants live in a separately owned role-policy stack. Use `aws/bedrock-access.ts` for immutable host/role inspection, exact change-set preview/apply/cancellation, replacement refusal and aggregate IAM quota/readback checks; never resynthesize the hosting stack to change model permissions. The selected route union covers all still-needed agent/default/fallback routes. Shared host teardown removes owned recovery and Bedrock policy stacks before deleting the role. Metadata discovery does not prove inference access.
- Native persistent model changes use `openclaw/model-control.ts` with the private local-port client in `model-client.ts`. Gateway revision tokens are opaque; preserve fallbacks, sibling settings and session overrides. Validate global changes in the explicit catalog contexts of inheriting agents. Check published defaults through the Gateway, require explicit controlled restart approval when reload is off, and never blindly retry an unacknowledged write. The host caller must fence writes with shared flock/maintenance and durable model-only records; do not persist raw native config/auth output.
- Bedrock role mode uses `openclaw/bedrock-profile.ts`'s private region-only AWS profile and additive native-service environment. It contains no credentials or credential process; the SDK still resolves IMDSv2. Do not copy an operator profile or invent a model API key. Refuse conflicting AWS identity/endpoint inputs privately before enabling it, preserve unrelated provider credentials, and prepare fresh role environment explicitly during restore/clone activation. AWS deployment region and Bedrock inference region have separate meanings.
- Local deployment metadata separates stable CloudFormation identity, desired settings and native observations. Observing drift does not authorize applying configuration changes. Preserve metadata on inspection failures; verify identity before destruction or secret cleanup.
- Reuse native OpenClaw backup, storage, agent and model semantics. AWS transports and provisioning receipts belong here; native archive formats and inference routing do not.
- Backup callers use `operations/backup.ts`. The host worker fences mutations with `flock` plus a durable maintenance record, uses explicit IMDSv2 role credentials independently of model-provider credentials, and only publishes capture metadata after full exact-version native verification. Completed AWS receipts are separate from the native catalog. Preserve prior Gateway state on both success and failure; never clear maintenance ownership based on age. Remove verified source recovery-access stacks before deleting a source role, and retain the independent vault/key.
- The native S3 plugin is authored in `src/openclaw/aws-s3-plugin/` and bundled separately by the build. Pin its public plugin SDK ABI to the tested OpenClaw release and keep dependency licenses in the artifact. Clean-client reads use the explicitly managed helper and pinned lockfile; never fall back to a global OpenClaw, inherited AWS profiles or the operator's native configuration. Native helper failures must not leak child environments/output. See `docs/native-backup-transport.md` for ownership and verification boundaries.
- New installations use the packaged bootstrap template and pinned installer inputs. Existing deployments are not implicitly upgraded or replaced. A failed AWS read is not permission to provision, destroy or clean up secrets.
- Fresh and restore setup use separate bootstrap assets. Fresh creation signals authenticated application readiness; a restore bootstrap signals only a pinned runtime with its Gateway masked/inactive. Never run fresh onboarding over restored state or treat the inactive runtime marker as an activated, healthy restoration.
- Recovery intake verifies the saved point before provisioning and inspects the immutable source stack ARN plus retained/replaced EC2 identities. A stopped or retained source is not a destroyed source. Native restore extracts into empty staging using exact object versions; adopt paths from its verified manifest, preserve the fresh installer-owned tools/bin, and journal data moves before renaming. Keep Gateway activation separate from staged-data installation and account for native automatic session recovery as well as channels and schedules.
- Restore staging uses `operations/restore.ts` and the bundled unprivileged restore worker. Recheck runtime, bootstrap and instance-role identities on retries; retain host maintenance ownership until activation is resolved. Reconcile auth through public config APIs, import only create-only operation-tagged target provider secrets and pause automatic integrations. Restored sessions use the native public archived-session hold with a private ownership journal; health checks must not implicitly release those holds. Shared checksummed artifact delivery downloads as root and executes only as Ubuntu.
- Restore activation is explicit. Verify paused integrations, all session holds and the fresh target SSM token before installing/starting the native service, then verify authenticated health and the holds again. Failed activation must reestablish a persistent inactive mask or report uncertainty. The durable host activation receipt permits reconciliation after a lost client reply. Resume reuses pinned request/code versions, verifies the target bootstrap operation and never recreates an absent deployment implicitly. Local restore journal results are historical metadata, not live ownership authority.
- Independent clones select verified workspace and file-backed skills content with `clone-content.ts`; never adopt source native databases/auth as a new identity. Source policy inspection uses `clone-source.ts`'s bounded archived include view and isolated public native reader, without following source absolute links into the live machine. Bind content, executable permissions and target role mappings to the preview digest. Fresh native onboarding/agent creation and public auth writers use only explicit target credentials; retain supported model restrictions/runtime selections and internal role permissions while withholding channels, schedules, hooks, indexing and external connections. Interrupted native initialization requires inspection/cleanup rather than onboarding over partial state. Provider onboarding/auth mappings belong in `install.ts`.
- Clean-client clone intake uses `operations/clone-preview.ts`, exact saved object/key versions and the managed helper's read-only bundled preview mode. Remove decrypted staging before returning either success or failure; reports contain selected content/policy digests and no physical staging paths or secret values. Preview does not provision AWS targets. Preserve persisted recovery artifact inventory compatibility when extending the shared worker bundle.
- Restore and clone share `operations/recovery-target.ts`, `provisionInactiveTarget` and `openclaw/recovery-staging.ts`. Reserve space for both extracted source data and selected clone copies. The locked clone worker binds the full request/preview, reads only operation-tagged target provider parameters, creates fresh native state, and deletes decrypted source staging before its ready receipt. Revalidate the certified native configuration on lost-reply adoption; never replay incomplete onboarding. Preserve the legacy `openclaw-aws:restore-id` inactive-bootstrap ownership tag across both paths, while recording independent `clonedFrom` deployment lineage and sharing immutable-identity cleanup.

- Clone client operations use explicit credential references, a private account/partition-pinned journal and the shared recovery delivery lease. Import target secrets as the operator with create-only ownership checks; clone host IAM grants tag inspection rather than secret writes. Remove source recovery access before activation and dispatch only checksum-pinned installed code; require actual source archive/key read denials through the instance role before an active clone can run. Service activation/rollback and lost-reply adoption are shared with restore through recovery-service.ts and recovery-activation-control.ts; receipt/release failures must also remask the service. See docs/independent-clones.md for content policy and retry boundaries.

Run build, typecheck, lint, formatting and the full Vitest suite for feature PRs. Local tunnel integration tests bind loopback ports and launch disposable local processes; they make no AWS calls. Live AWS acceptance is separate and needs a concrete approved account/region/resource/budget/cleanup scope. Keep transient execution tracking in the requested local Markdown plan, outside feature commits.

- Restored deployment metadata records backup/operation lineage without inventing an Anthropic default. Cleanup uses immutable stack identity plus operation tags, inventories all parameter ownership before deletion, and deletes the Gateway namespace sentinel last. Declared npm plugin rebuilds use exact public registry provenance and native install policy, with integrity/configuration rechecks; per-agent temporary diagnostic views must not alter the saved system owner. Reactivate reviewed work through native restore-from-archive or new-thread semantics, preserving the no-replay adoption hold on historical work.
